## DM 한 통의 재료

| 영역 | 어디서 | 메모 |
| --- | --- | --- |
| 📌 업무 | BOT_TASKS (업무 시트 3개에서 6종 추출) | 종료 임박·헤즈업·예비 작업자 검토·어뷰저·1차 검수·테스트지 |
| 📅 회의 | 연결 앱이 보낸 본인 회의 캐시(BOT_CALENDAR_PERSONAL) | 20분보다 오래되면 "갱신 지연"과 "내 일정 갱신" 링크 |
| 💬 Slack | 미리 만든 수집본(60분 안) | 같은 종류의 업무가 있으면 업무 줄 아래 "관련 Slack"으로 옮김 |
| 🍚 점심 · ✨ 한마디 | 봇 시트 BOT_RESTAURANTS / BOT_PHRASES | 오전 DM만 점심. PM·날짜별로 고정 선택, 최근 반복 제외 |

## 실패해도 멈추지 않는 부분

- **Slack 수집본이 없거나 오래됨:** 업무·회의는 보내고, Slack 영역에 "읽어오지 못했습니다 — 사유"를 적습니다.
- **회의 조회 실패:** 회의 영역에 안내만 적고 나머지는 보냅니다.
- **점심·한마디 데이터 오류:** 그 영역만 뺍니다.
- **명단 문제(BOT_USERS):** Slack ID 형식 오류·같은 이름이나 ID가 두 줄 → 그 PM만 이번 회차에서 뺍니다. 업무 시트 담당자 이름과 다름 → 업무 영역에 안내를 적고 나머지는 보냅니다. 캘린더 연결 명단의 이메일 중복도 그 줄만 뺍니다. 모두 관리자 요약에 "명단 확인 필요"로 나옵니다.
- **한 PM 문안 준비·발송 실패:** 다른 PM은 계속 보냅니다. 결과가 불분명한 PM에게는 자동으로 다시 보내지 않습니다(중복 DM 방지).
- **Slack 요청 제한(429):** 기다렸다가 이어 보냅니다.
- **공휴일 캘린더 조회 실패:** 근무일로 보고 보냅니다(놓치는 것보다 한 통 더 가는 쪽이 안전).
- **연차인 PM:** 본인 캘린더 연결 자료에 09~18시를 모두 덮는 "연차·휴가" 일정(반차 제외, 다른 PM 이름이 든 제목 제외)이 있으면 그 PM만 회차에서 빼고 발송 기록에 `skipped-leave`로 남깁니다. 연결 자료를 못 읽으면 보냅니다.
- **회차가 아예 안 돎:** 다음 회차의 관리자 요약에 "직전 회차 발송 기록 없음"이 나옵니다. 모든 회차가 멈추면(권한 만료 등) 요약도 오지 않으니 Google의 트리거 실패 메일로 확인합니다.

## 저장 위치

| 위치 | 내용 |
| --- | --- |
| 봇 시트 탭 | BOT_USERS(이름·Slack ID·발송·이메일·캘린더 연결 체크), BOT_TASKS, BOT_SEND_LOG(90일), BOT_DAILY_HISTORY(90일), BOT_SLACK_*(수집 캐시·수집본), BOT_CALENDAR_PERSONAL, BOT_PHRASES, BOT_RESTAURANTS, BOT_FEEDBACK(👍/👎 기록), 폼 응답 탭, BOT_SETTINGS(설정 입력용, 반영 후 비움) |
| 스크립트 속성 | 설정 스위치, 토큰, PM별 Slack 표시 기록·점심/한마디 이력, 회차 진행 상태. 관리자 요약에 사용량(KB/500KB)이 나옵니다. |

## 버튼이 눌렸을 때 (점심 메이트 · 피드백)

```text
PM이 DM의 버튼 누름
  → Slack이 "누가·무슨 버튼"을 중앙 봇 웹 앱 주소로 보냄 (Interactivity Request URL)
  → doPost가 Slack 요청인지 연결 앱 요청인지 구분
  → 검증 값(SLACK_VERIFICATION_TOKEN) 확인
  → 점심 메이트: 누른 사람의 LUNCH_MATE_<Slack ID> = on/off 저장 → 다음 10:30 DM부터 반영
  → 피드백 👍/👎: BOT_FEEDBACK 탭에 한 줄 추가 (✍️는 구글 폼이 바로 열림, 기록 없음)
  → 누른 사람에게만 보이는 답장
```
