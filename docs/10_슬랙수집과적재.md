# 10. Slack 수집과 시트 적재

> 11/24 현재 판소리 기준: [운영 안내](PANSORI_SETUP.md). 답장 자동 판정은 제거됐으며, 이전 실험 설명보다 현재 안내를 우선한다.

Slack을 **언제, 무엇을, 어떻게 읽어서 봇 시트 어디에 쌓는지**, 그리고 DM을 만들 때 그 자료를 어떻게 꺼내 쓰는지 정리한 문서입니다. 코드는 `03_슬랙수집.js`(합본 `3_슬랙.gs`), 판소리 부분은 `33_판소리.js`입니다.

## 한눈에 보기

```
[10분 트리거] collectBbpmSnapshot
   │  수집 시간대(09:45~10:45 · 13:30~14:15 · 16:00~17:15)이고, 평일이고, 25분 안에 만든 수집본이 없을 때만
   ▼
① 설정 읽기 ── 토큰 · PM 그룹 · 기간(7일) · BBPM 등록 스레드 · 판소리 스레드(PANSORI_THREADS)
   ▼
② 채널 훑기 ── #pm_team_channel 이력을 페이지로 읽어 후보를 BOT_SLACK_DISCOVERY_CACHE에 쌓음
   ▼
③ 답글 읽기 ── 스레드마다 부모글 + 답글을 읽어 BOT_SLACK_REPLY_CACHE에 쌓음 (판소리 스레드도 여기)
   │  ②③은 한 번에 4.5분까지. 못 끝내면 진행 위치를 저장하고 다음 10분 트리거가 이어 읽음
   ▼
④ 수집본 저장 ── 멘션이 있는 글만 골라 BOT_SLACK_SNAPSHOT_A / B 중 안 쓰는 쪽에 통째로 씀 → 활성 탭 전환
   ▼
[발송 · 미리보기] 활성 수집본을 읽어 PM마다 분류 → DM의 💬 Slack 칸
```

수집과 발송은 **분리**돼 있습니다. 발송은 Slack을 직접 읽지 않고, 미리 만든 수집본만 읽습니다. 그래서 Slack이 느리거나 막혀도 DM은 제시간에 나가고, Slack 칸에만 "읽어오지 못했습니다 — 사유"가 붙습니다.

## ① 설정 읽기 — `readSlackMentionConfig_`

| 설정 (스크립트 속성) | 뜻 |
| --- | --- |
| `ENABLE_SLACK_MENTION_READ` | `true`일 때만 Slack을 읽음 |
| `SLACK_BOT_TOKEN` | 봇 토큰(`xoxb-`). 로그에 찍지 않음 |
| `SLACK_PM_GROUP_ID` | PM 그룹(@멘션 그룹) ID. 그룹 멘션 글을 누구에게 보일지 정할 때 씀 |
| `SLACK_MENTION_LOOKBACK_DAYS` | 몇 일 전 글까지 볼지. 기본 7 |
| `SLACK_MENTION_THREADS` | BBPM에서 꼭 읽을 스레드 링크 JSON 배열(1~5개) |
| `ENABLE_SLACK_CHANNEL_DISCOVERY` · `SLACK_DISCOVERY_CHANNEL_ID` | 채널 전체 훑기 켜기 · 대상 채널. 미리 수집은 이게 켜져 있어야 함 |
| `ENABLE_PANSORI_READ` · `PANSORI_RECIPIENT_IDS` · `PANSORI_THREADS` | 판소리 스레드 추가(아래 "스레드 목록을 설정으로 관리하는 방법") |

## ② 채널 훑기 — `discoverBbpmThreadsBatch_`

- Slack `conversations.info`로 채널 이름이 승인된 채널(`pm_team_channel`)인지 먼저 확인합니다. 다른 채널은 훑지 않습니다.
- `conversations.history`로 채널 이력을 100개씩 거꾸로 읽습니다. 후보로 남기는 글은 두 가지입니다.
  - 최근 7일 안에 쓴 글
  - 7일보다 오래된 부모글이지만 **최근 7일 안에 답글이 달린 글** (오래된 스레드의 새 답글을 놓치지 않으려고)
- 후보는 봇 시트 `BOT_SLACK_DISCOVERY_CACHE` 탭에 `message_ts | candidate_json` 줄로 덧붙입니다. 어디까지 읽었는지(페이지 커서)는 스크립트 속성 `BBPM_DISCOVERY_CHECKPOINT`에 둡니다.
- 페이지가 반복되거나 응답이 불완전하면 멈춥니다(빠진 채로 완료본을 만들지 않음).

## ③ 답글 읽기 — `collectBbpmRepliesBatch_`

- 읽을 스레드 = BBPM 등록 스레드 + ②에서 찾은 "답글 있는 부모글" + **판소리 스레드**.
- 스레드마다 `conversations.replies`로 부모글 1개, 답글 페이지를 차례로 읽어 `BOT_SLACK_REPLY_CACHE` 탭에 한 줄에 글 하나(JSON)로 덧붙입니다. 분류에 쓰지 않는 첨부·반응·blocks는 버리고 `ts · text · user · bot_id · subtype · 채널 · 스레드 · 부모글 본문`만 남깁니다.
- 몇 번째 스레드의 어느 페이지까지 읽었는지도 `BBPM_DISCOVERY_CHECKPOINT`에 저장합니다. 스레드 목록이 바뀌면(서명 비교) 답글 캐시를 비우고 처음부터 읽습니다.
- 판소리 스레드는 다른 채널에 있어도 됩니다. 채널 전체를 훑지 않고 **지정한 스레드만** 읽습니다.

### 시간·호출 제한과 이어 읽기

- Apps Script 한 번 실행은 6분이 한계라서 **4.5분 또는 Slack 호출 300번**이 되면 멈추고 "진행 중"으로 끝냅니다. 10분 뒤 트리거가 저장된 위치부터 이어 읽습니다.
- Slack이 읽기 제한(429)을 주면 기다릴 시간을 기록하고 이번 실행을 끝냅니다. 다음 실행이 이어 받습니다.
- 수집이 두 개 동시에 돌지 않도록 짧은 잠금 + 점유 표시(`BBPM_COLLECT_LEASE`)를 씁니다. 발송은 이 잠금을 기다리지 않습니다.

## ④ 수집본 저장 — `writeBbpmSnapshot_`

- ②③이 모두 끝나야만 저장합니다. 중간 결과는 수집본이 되지 않습니다.
- 저장 대상은 **멘션이 있는 글**(`<@사람>`, `<!subteam^그룹>`, `@here`, `@channel`)이고 조회 기간 안의 글뿐입니다. 멘션이 없는 글은 누구의 할 일도 아니므로 버립니다.
- `BOT_SLACK_SNAPSHOT_A`와 `_B` 두 탭을 **번갈아** 씁니다. 지금 쓰는 쪽은 그대로 두고 반대쪽을 지운 뒤 통째로 쓰고, 다 쓰면 `BBPM_SNAPSHOT_SLOT` 속성을 바꿔 활성 탭을 넘깁니다. 쓰는 도중에 발송이 와도 직전 완료본을 온전히 읽습니다.
- 탭 구조: 1행 머리글 `snapshot_json`, 2행 **메타**, 3행부터 글 하나당 한 줄(JSON).

| 메타 필드 | 뜻 |
| --- | --- |
| `newest` · `oldest` | 이 수집본이 덮는 기간(초) |
| `members` | 수집 당시 PM 그룹 멤버 ID 목록 |
| `groupId` · `botId` | PM 그룹 ID, 봇 자신의 ID(봇이 쓴 글은 분류에서 뺌) |
| `pansori` | 수집 당시 판소리 설정(스레드 목록 + 수신자). 아래 안전장치에 씀 |
| `messageCount` · `savedAt` | 글 수, 저장 시각 |

- 상태는 스크립트 속성에도 남습니다: `BBPM_COLLECT_STATUS`(running / pending / complete / error), `BBPM_COLLECT_LAST_ERROR`(실패 사유, 성공하면 지움), `BBPM_COLLECT_LAST_TRIGGER_AT`.

## 발송할 때 꺼내 쓰기 — `loadFreshBbpmSnapshot_` → `classifySlackSnapshot_`

1. 활성 탭의 수집본을 읽고 검사합니다. 실패하면 사유 코드가 붙고 DM Slack 칸에 짧은 사유가 나옵니다.

| 검사 | 실패 코드 | DM 사유 |
| --- | --- | --- |
| 수집본 있음 | `NO_SNAPSHOT` | 완료된 수집 자료 없음 (+ 마지막 수집 오류로 원인 좁힘) |
| 만든 지 60분 안 (본인 시험·미리보기는 하루) | `STALE` | 최신성 기준 초과 / 권한·토큰·읽기 제한 |
| PM 그룹 설정이 수집 때와 같음 | `CONFIG_CHANGED` | Slack 설정 변경 뒤 아직 다시 수집 전 (다음 수집 뒤 반영) |
| 판소리 설정이 수집 때와 같음 | (막지 않음) | BBPM은 그대로 보이고, 판소리는 수집 때와 지금 설정에 **모두 있는** 스레드·수신자만. 빠진 스레드 글은 아예 뺌. 새로 넣은 것은 다음 수집부터 (11/24 밤부터, 전에는 Slack 칸 전체를 비웠음) |

2. PM마다 분류합니다(`classifySlackMentionMessages_`).
   - 봇 자신의 글, 삭제·수정 표시 글, 기간 밖 글은 뺍니다. 같은 글은 한 번만 봅니다.
   - **판소리 스레드의 글**이면 판소리 규칙(`pansoriMentionRecords_`)으로 넘깁니다. 담당자 블록·내 줄만·@here 부분·할 일 목록·회신 요청을 판정합니다(답장 자동 판정은 11/24 저녁 제거).
   - 그 밖의 글은 그 PM을 직접 멘션했거나(direct), PM 그룹을 멘션했고 그 PM이 그룹 멤버면(group) 그 PM의 항목이 됩니다. `@here`·`@channel`만 있는 BBPM 글은 저장은 되지만 누구에게도 배정되지 않습니다.
3. 이후 `04_슬랙업무분류.js`가 요청 종류·기한을 붙이고, 이미 보낸 항목은 접거나 숨기고, 같은 종류의 업무 줄 아래로 옮겨 DM 문안을 만듭니다.

## 스레드 목록을 설정으로 관리하는 방법 (판소리, 11/24)

판소리 스레드 번호는 코드에 없습니다. 봇 시트에 적은 **링크를 수집할 때마다 읽어서** 정합니다.

1. **입력:** 봇 시트 `BOT_SETTINGS`의 `PANSORI_THREADS` 줄 B열에 Slack "링크 복사" 주소를 쉼표로 이어 적고 `applyBotSettings`를 실행합니다. 허용 목록(`27_설정반영.js`)에 있는 이름만 스크립트 속성으로 옮겨집니다.
2. **해석:** `readPansoriRoute_`(33번)가 값을 쉼표·공백으로 나누고, BBPM 스레드에 쓰던 `parseSlackMentionThreadUrl_`로 링크마다 채널 ID와 스레드 번호를 꺼냅니다.
   - 예: `…/archives/C…/p1700000000000001` → 채널 `C…`, 스레드 `1700000000.000001`
   - 같은 스레드는 한 번만, 최대 20개. 링크가 아닌 값이 있거나 비었거나 20개를 넘으면 **판소리만 건너뛰고** BBPM 수집은 그대로 돕니다.
3. **수집:** 해석된 스레드를 ③의 스레드 목록 뒤에 붙입니다(`readSlackMentionConfig_`).
4. **분류:** 글의 채널·스레드가 이 목록에 있을 때만 판소리 규칙으로 분류합니다.
5. **안전장치:** 수집본 메타에 그때의 판소리 설정을 저장하고, DM을 만들 때 지금 설정과 비교합니다. 다르면 **겹치는 스레드·수신자만** 판소리로 쓰고, 빠진 스레드의 글은 수집본에서 빼서 BBPM 규칙으로도 다시 분류되지 않게 합니다. 스레드를 빼거나 수신자를 바꿨는데 예전 자료가 다른 사람에게 가는 것을 막으면서, BBPM 칸은 비우지 않습니다. 관리자 요약과 미리보기에 "판소리 설정이 마지막 수집 뒤 바뀜"이 뜹니다.

**리드가 스레드를 새로 만들면:** `PANSORI_THREADS` 끝에 `, 새링크`를 붙이고 `applyBotSettings`. 코드 수정·업로드는 필요 없습니다.

**주의 — 수집 시간대 전에 바꾸기:** 새로 넣은 스레드는 다음 수집이 끝나야 보입니다. 11/24 오후에는 이 경우 Slack 칸 전체가 "기타 오류"로 비었는데(14:12·14:38 미리보기, 16:00 수집 뒤 정상), 같은 날 밤부터는 BBPM은 계속 보이고 판소리만 다음 수집을 기다립니다. 그래도 수집 시간대(09:45~10:45 · 13:30~14:15 · 16:00~17:15) **시작 전**에 바꾸면 바로 다음 DM에 반영됩니다.

## 저장 위치 요약

| 위치 | 무엇 | 누가 지우나 |
| --- | --- | --- |
| `BOT_SLACK_DISCOVERY_CACHE` | 채널 훑기 후보(진행 중 자료) | 새 수집이 시작될 때 비우고 다시 씀 |
| `BOT_SLACK_REPLY_CACHE` | 스레드 부모글·답글(진행 중 자료) | 스레드 목록이 바뀌거나 새 수집일 때 |
| `BOT_SLACK_SNAPSHOT_A` / `_B` | 완료본(발송이 읽는 것) | 번갈아 덮어씀 |
| 스크립트 속성 `BBPM_DISCOVERY_CHECKPOINT` | 어디까지 읽었는지 | 봇이 관리 |
| `BBPM_SNAPSHOT_SLOT` | 지금 활성 탭(A/B) | 봇이 관리 |
| `BBPM_COLLECT_STATUS` · `_LAST_ERROR` · `_LEASE` | 수집 상태 · 실패 사유 · 동시 실행 방지 | 봇이 관리 |

모든 탭과 속성은 **봇 전용 시트·봇 스크립트**에만 있습니다. Slack 쪽은 읽기만 하고(`chat:write`는 DM 발송용), 원본 업무 시트에는 쓰지 않습니다.

## 점검할 때

- 수동 수집: 편집기에서 `collectBbpmSnapshot` 실행(시간대와 상관없이 바로 수집, DM 없음). "진행 중"이면 한 번 더 실행하면 이어 읽습니다.
- Slack 칸 사유가 "기타 오류"면 실행 로그에서 `원인:` 뒤 문구를 봅니다. "설정 변경 뒤 아직 다시 수집 전"이면 다음 수집 완료를 기다리거나 수동 수집합니다.
- `previewMyMorningBriefing` 로그 맨 끝에 ⚠️ 줄이 있으면 먼저 봅니다: 오늘 업무 갱신 전·업무 시트 읽기 실패(직전 결과 유지)·최근 Slack 수집 오류·판소리 설정 변경.
- 판소리 판정이 의심되면 `checkPansoriClassification`(점검표, 아래 판소리 안내).
- 더 넓은 점검 순서는 [06 '업무 없음'과 '수집 실패' 점검](06_없음과수집실패점검.md), 설정 목록은 [09 운영 환경 스펙](09_운영환경스펙.md), 판소리 표시 규칙은 [판소리 안내](PANSORI_SETUP.md).
