# 판소리 운영 안내 — 현재 기준

## 무엇을 하는 기능인가

등록한 판소리 회의공지·업무요청 스레드를 읽고, 본인에게 온 요청과 판소리 공통 안내를 기존 개인 DM에 추가한다. BBPM 연결은 유지한다.

## 작동 순서

1. 관리자가 읽을 스레드와 받을 사람을 설정한다.
2. 봇이 등록 스레드의 최근 메시지를 읽어 봇 전용 수집 시트에 저장한다.
3. 본인 멘션·공통 멘션을 구분하고, 담당자 아래 설명과 기한을 추출한다.
4. 키워드로 업무 종류를 붙이고 원문 링크·작성일·명시 기한을 정리한다.
5. 회차별 기준에 맞는 항목만 해당 사람의 DM에 포함한다.

## 회차별 표시

| 시각 | 판소리 Slack 안내 |
| --- | --- |
| 10:30 | 발송 이력상 새 요청·변경 안내. 기존 오늘 기한 정책도 적용 |
| 14:00 | 아직 안내하지 않은 새·변경 항목만 |
| 17:00 | 새·변경 항목과 최근 조회 범위의 회신 요청 재안내 |

**회신 요청은 실제 미회신을 뜻하지 않는다.** 부탁·답변·의견 요청 등의 표현을 찾아 재확인을 돕는 안내다. 같은 스레드에 답해도 요청을 숨기지 않는다. 원문 읽음·완료·취소를 자동 확정하지 않는다.

## 관리자가 설정하는 것

| 설정 | 의미 |
| --- | --- |
| `ENABLE_PANSORI_READ` | true일 때 판소리 읽기 활성 |
| `PANSORI_RECIPIENT_IDS` | 봇 명단과 일치하는 수신자 Slack ID JSON 배열 |
| `PANSORI_THREADS` | 읽을 스레드 메시지 링크. 최대 20개, 쉼표로 구분 |

- 봇이 해당 채널에 참여하고 필요한 읽기 권한을 가지고 있어야 한다.
- 스레드 설정은 봇 전용 BOT_SETTINGS 탭과 applyBotSettings 또는 스크립트 속성에서 관리한다. 실제 링크·개인 ID·토큰은 저장소 문서에 넣지 않는다.
- 설정 변경 뒤에는 새 수집을 완료해야 새 스레드·수신자가 반영된다. 그 전까지 BBPM은 그대로 보이고, 판소리는 수집 때와 지금 설정에 모두 있는 스레드·수신자만 보인다(빠진 스레드 글은 숨김). 관리자 요약·미리보기에 "판소리 설정이 마지막 수집 뒤 바뀜"이 뜬다. 설정은 수집 시간대 전에 바꾸는 것이 좋다.
- 스레드 설정이 없거나 잘못되면 현재 코드는 판소리 읽기를 건너뛴다. 켜짐 설정만으로 정상 수집을 단정하지 않는다.

## 실행할 함수와 영향

모두 Apps Script 편집기 **3_슬랙** 파일에 있다.

| 함수 | 쓰는 상황 | 실제 영향 |
| --- | --- | --- |
| configureMyPansoriBriefing | 본인 연결을 처음 설정 | 실행 계정과 봇 명단 확인 후 수신자·활성 속성 저장. DM 없음 |
| previewPansoriBriefing | 연결·분류를 직접 확인 | 등록 스레드를 직접 조회하고 로그 출력. 저장·DM 없음. 정기 DM 선택과 동일한 미리보기는 아님 |
| checkPansoriClassification | 판정이 맞는지 한 번에 점검(리드 글이 20~30개 쌓였을 때 권장) | 저장된 수집본의 판소리 글마다 누구에게(멘션된 사람 전원 기준) 어떤 종류·기한·회신 요청으로 붙었는지와 ⚠️ 의심 사례(멘션이 있는데 아무에게도 안 붙음, 멘션 수보다 적게 붙음, 담당 구분 실패, 업무 종류 못 정함, 기한 여러 개)를 로그로. Slack 조회·저장·DM 없음 |
| collectBbpmSnapshot | 정기 DM용 자료 준비 | BBPM과 설정된 판소리 스레드를 읽고 봇 전용 캐시·완료본 저장. DM 없음 |

전체 DM 확인은 **1_자동실행과발송 → previewMyMorningBriefing / previewMyEveningBriefing**. 저장된 자료를 사용하며 DM은 보내지 않는다.

## 분류를 추가·수정하는 방법

- 원본: `apps-script-linked/33_판소리.js`의 `PANSORI_CATEGORIES`.
- name은 DM의 분류 이름, keywords는 찾을 단어나 정규식이다. 여러 규칙이 맞으면 위 규칙 우선.
- 현재 분류: 회의·안건·회의록 / 모집·스크리닝·참여자 안내 / 가이드·계약 문서 검토 / 녹음 준비·환경 테스트·운영 시트 / 데이터 검수·납품·정산.
- 판소리 사전은 기존 BBPM의 BOT_KEYWORD_RULES와 별도로 관리한다.
- 변경 후 전체 테스트 → 합본 빌드 → 원격 충돌 확인 → 업로드 → 재조회 일치 확인.

## 정확도와 보호 기준

- 개인 멘션과 공통 안내는 설정된 수신자에게만 전달한다. cc는 직접 요청에서 제외한다.
- 담당자 아래 들여쓴 설명·기한을 보존하며 다른 담당자가 섞이면 원문 확인으로 둔다.
- @here 공지에 개인 요청이 섞이면 비담당자에게는 공통 앞부분만 안내한다. 모든 문장 구조를 이해하는 것은 아니다.
- 기한은 규칙으로 발췌한다. 한 줄에 여러 시각이 있으면 요청 표현 앞의 값을 우선하는 휴리스틱이므로 원문 확인이 필요할 수 있다.
- 날짜가 명확하게 지난 회의 초대는 DM에서 제외하되, 회의록 작성·검토 업무와 미래·반복·불명확 일정은 보존한다.
- 원본 업무 시트, Slack 메시지, 캘린더 일정을 변경하지 않는다.
