## 연결

Apps Script 프로젝트 설정 → 스크립트 속성:

- `ENABLE_PANSORI_READ`: `true`로 활성화. 없거나 false면 기존 BBPM만 동작.
- `PANSORI_RECIPIENT_IDS`: 판소리 수신자의 Slack 멤버 ID JSON 배열. BOT_USERS의 ID와 일치해야 한다. **11/24 현재 담당자 본인 1명만** (`configureMyPansoriBriefing`으로 추가).
- `PANSORI_THREADS`: 읽을 판소리 스레드의 **Slack 메시지 링크**(링크 복사). 여러 개는 쉼표로 구분, 최대 20개. 봇 시트 BOT_SETTINGS에 적고 `applyBotSettings`로 반영한다. **없으면 판소리 읽기만 건너뛰고 기존 BBPM은 그대로 돈다.** 채널·스레드 번호는 코드에 두지 않는다(11/24부터).
  - 리드가 아이템별 스레드로 나누면 그 링크를 여기에 추가하면 된다. 코드 수정·업로드가 필요 없다.
  - 값을 바꾸면 다음 수집이 끝날 때까지 직전 완료본을 쓰지 않는다. 수집 시간대(09:45~10:45 · 13:30~14:15 · 16:00~17:15) **전에** 바꾼다.
- 예시(실제 ID 아님): `["U00000001","U00000002"]`
- 봇이 해당 채널을 읽을 수 있어야 한다. 채널 초대 및 읽기 권한은 별도 확인한다.
- 기존 BBPM 설정은 유지한다. 판소리는 지정된 회의공지·업무요청 두 스레드만 기존 이어 읽기 큐에 추가한다. 채널 전체 자동 발견은 하지 않는다.
- 기존 수집 체크포인트와 호출 예산을 공유한다. 판소리 수집 실패 시 전체 새 완료본은 게시하지 않는다. 채널별 독립 수집은 아직 구현하지 않았다.
- 수신 설정을 바꾸면 새 수집 완료 전 기존 완료본 사용을 차단한다.

## 분류 추가·수정

- 로컬 원본 `apps-script-linked/33_판소리.js`의 `PANSORI_CATEGORIES`를 편집한다.
- `name`: DM에 표시하는 업무 이름. `keywords`: 해당 분류로 판단할 검색 표현(정규식).
- 예: `{name:'녹음 준비', keywords:/녹음 준비|소음 테스트|기기 세팅/}`
- 여러 규칙이 맞으면 위에서부터 첫 규칙을 사용한다. 세부 규칙을 넓은 규칙보다 먼저 둔다.
- 판소리 분류는 BOT_KEYWORD_RULES가 아닌 이 전용 사전에서 관리한다. 기존 BBPM 사전은 변경하지 않는다.
- 수정 → `node tools/test-local.cjs` → 빌드 → 원격 충돌 확인 → 업로드 → 재조회 검증.

## 정확도 기준과 남은 작업

- 명시적인 `담당자:` 블록은 개별 분리하고, 담당자 블록이 없으면 내 멘션 줄과 상위 소제목만 뽑는다(①). 같은 줄에 여러 명이면 원문 확인.
- cc는 직접 요청으로 취급하지 않는다. 여러 담당자가 섞이면 기한을 배정하지 않고 확인 요청으로 표시한다.
- @here/@channel 공통 안내는 설정한 판소리 수신자에게만 전달한다. 같은 글에 특정 사람에게 따로 맡긴 줄이 섞여 있으면, 그 사람에게는 글 전체를, 나머지 수신자에게는 **@here 부분(다른 사람을 처음 멘션한 줄 전까지)만** 보인다(11/24 저녁). 단순 응답·멘션 없는 일반 댓글은 자동 업무로 만들지 않는다.
- 취소선·인용문을 담당자 판정에서 제외한다.
- 미정·보류·의견 요청은 확인·회신으로 표시한다. 이전 요청을 찾아 취소·완료시키지 않는다.
- 새 댓글은 별도 항목으로 유지한다. 최신 글이 과거 요청의 최종 결정이라고 단정하지 않는다.
- 회의는 Slack 원문 링크를 안내하고, 위클리 당일에는 캘린더 일정과 회의록 요청을 묶어 한 줄로 보인다(④). 일정 충돌 자동 비교는 하지 않는다.
- 내 담당 아래 들여쓴 설명·기한을 다음 담당 구간 전까지 보존한다. 하위에 다른 담당자가 섞이면 원문 확인으로 둔다.
- 답장 자동 판정은 판소리·BBPM 모두 사용하지 않는다.
- 과거 담당자의 업무를 신규 합류자에게 자동 이전하지 않는다.
