# 판소리 연결·업무 분류 안내

현재 상태: 40개 테스트 통과·원격 업로드·8파일 재조회 일치 확인 완료. 본인 활성화·실제 수집·DM 수신 미검증.

## 연결

Apps Script 프로젝트 설정 → 스크립트 속성:

- `ENABLE_PANSORI_READ`: `true`로 활성화. 없거나 false면 기존 BBPM만 동작.
- `PANSORI_RECIPIENT_IDS`: 판소리 수신자의 Slack 멤버 ID JSON 배열. BOT_USERS의 ID와 일치해야 한다.
- 예시(실제 ID 아님): `["U00000001","U00000002"]`
- 봇이 해당 채널을 읽을 수 있어야 한다. 채널 초대 및 읽기 권한은 별도 확인한다.
- 기존 BBPM 설정은 유지한다. 판소리는 지정된 회의공지·업무요청 두 스레드만 기존 이어 읽기 큐에 추가한다. 채널 전체 자동 발견은 하지 않는다.
- 기존 수집 체크포인트와 호출 예산을 공유한다. 판소리 수집 실패 시 전체 새 완료본은 게시하지 않는다. 채널별 독립 수집은 아직 구현하지 않았다.
- 수신 설정을 바꾸면 새 수집 완료 전 기존 완료본 사용을 차단한다.

## 실행

- `configureMyPansoriBriefing` — `3_슬랙.gs`: 회사 계정으로 1회 실행. 본인 수신자·활성 속성만 저장. DM 없음.
- `previewPansoriBriefing` — `3_슬랙.gs`: 지정 두 스레드 최근 7일의 본인 분류 로그. 저장·DM 없음.

- `collectBbpmSnapshot` — `3_슬랙.gs` (로컬 원본 `03_슬랙수집.js`): 기존 BBPM과 설정된 판소리 스레드 수집. DM 발송 없음.
- 기존 분류 미리보기와 정기 DM이 새 분류를 사용한다. 판소리 전용 발송 함수·트리거는 추가하지 않는다.
- 원격 업로드 전에는 위 설정을 활성화하지 않는다.

## 분류 추가·수정

- 로컬 원본 `apps-script-linked/33_판소리.js`의 `PANSORI_CATEGORIES`를 편집한다.
- `name`: DM에 표시하는 업무 이름. `keywords`: 해당 분류로 판단할 검색 표현(정규식).
- 예: `{name:'녹음 준비', keywords:/녹음 준비|소음 테스트|기기 세팅/}`
- 여러 규칙이 맞으면 위에서부터 첫 규칙을 사용한다. 세부 규칙을 넓은 규칙보다 먼저 둔다.
- 판소리 분류는 BOT_KEYWORD_RULES가 아닌 이 전용 사전에서 관리한다. 기존 BBPM 사전은 변경하지 않는다.
- 수정 → `node tools/test-local.cjs` → 빌드 → 원격 충돌 확인 → 업로드 → 재조회 검증.

## 정확도 기준과 남은 작업

- 명시적인 `담당자:` 블록만 개별 분리한다. 자유형식 번호 목록·담당자 생략은 완전 자동 분리가 아니다.
- cc는 직접 요청으로 취급하지 않는다. 여러 담당자가 섞이면 기한을 배정하지 않고 확인 요청으로 표시한다.
- @here/@channel 공통 안내는 설정한 판소리 수신자에게만 전달한다. 단순 응답·멘션 없는 일반 댓글은 자동 업무로 만들지 않는다.
- 취소선·인용문을 담당자 판정에서 제외한다.
- 미정·보류·의견 요청은 확인·회신으로 표시한다. 이전 요청을 찾아 취소·완료시키지 않는다.
- 새 댓글은 별도 항목으로 유지한다. 최신 글이 과거 요청의 최종 결정이라고 단정하지 않는다.
- 회의는 Slack 원문 링크를 안내한다. 캘린더 중복 제거·일정 충돌 자동 비교는 아직 구현하지 않았다.
- 과거 담당자의 업무를 신규 합류자에게 자동 이전하지 않는다.
