# 00. 운영자 빠른 시작

코드 수정 없이 정상 운영과 장애를 구분하는 안내입니다. 평소에는 자동 DM과 관리자 요약을 확인합니다. 이 문서는 실제 계정·주소·토큰을 보관하지 않습니다.

## 1. 어디를 열면 되나요?

| 위치 | 용도 |
| --- | --- |
| 중앙 봇 Apps Script | 정기 DM·Slack 수집·운영 점검. 아래 합본 파일 이름을 찾습니다. |
| 별도 캘린더 연결 앱 | PM이 회사 Google 계정으로 승인하고 자신의 일정을 갱신합니다. |
| 봇 전용 시트 | BOT_USERS: 수신자 / BOT_TASKS: 업무 후보 / BOT_SEND_LOG: 발송 기록 / BOT_SETTINGS: 허용 설정 / BOT_FEEDBACK: 평가 |
| Slack 관리자 요약 DM | 해당 회차 발송 결과·문제 대상·다음 조치 |

**원본·운영 업무 시트는 변경하지 않습니다.** 운영 점검만 하려면 아래 조회 함수부터 사용합니다. 원본 읽기도 별도 허용된 목적·범위 안에서만 수행합니다.

## 2. 매일 3분 확인

1. 10:30·14:00·17:00 부근에 내 DM과 관리자 요약이 왔는지 확인합니다. 정각은 보장되지 않으며 이어 보내기는 회차 시작 후 최대 20분입니다.
2. 요약의 **미발송 / 확인 필요 / 직전 회차 누락 / 일정 갱신 지연**을 확인합니다. 일부 PM만 성공한 것을 전체 정상으로 보지 않습니다.
3. 조치할 항목이 없으면 종료합니다. **'업무 없음'만으로 원천 수집이 완전하다고 확정하지 않습니다.** [없음과 수집 실패 점검](06_없음과수집실패점검.md)을 참고하세요.

## 3. 문제가 생기면 이 순서

아래는 모두 **중앙 봇 프로젝트**에서 실행합니다. 파일과 함수를 함께 확인하세요.

| 증상 | 합본 파일 → 함수 | 결과와 다음 행동 |
| --- | --- | --- |
| 아무도 DM을 못 받음 / 관리자 요약도 없음 | `1_자동실행과발송` → `previewBriefingAutomationStatus` | 현재 실행 계정의 수집 1개·발송 3개 트리거, 전체 스위치, 수집 시각 확인. 조회만. 실패하면 편집기 '실행'에서 원래 오류 확인. |
| 한 PM만 누락 | `1_자동실행과발송` → `previewAdminRoundSummary` | 명단 오류·연차·미발송 대상 확인. 현재 저장 상태로 문안을 재구성하는 조회이며 새 DM을 보내지 않음. 과거 실제 수신 증빙은 아님. |
| 회의만 비거나 지연됨 | `4_캘린더연결` → `previewConnectedCalendarStatus` | 연결 여부·실제 자동 갱신 시각 확인. 해당 PM이 회사 계정으로 연결 화면의 '지금 갱신' 사용. 계속 실패하면 개발 담당자에게 연결 앱 접근·트리거 권한 확인 요청. |
| Slack만 비거나 오래됨 | `1_자동실행과발송` → `previewBriefingAutomationStatus`, 이어 `3_슬랙` → `previewSavedSlackBriefings` | 첫 함수는 수집 완료/지연 확인, 두 번째는 **저장된** 분류 목록만 확인. 새 수집이나 미확인 판정은 하지 않음. |
| 업무가 있는데 '없음'이라고 옴 | `6_공통설정과점검` → `previewBriefingAccuracy` | 봇에 **이미 적재된** 내 업무·Slack 포함/제외 목록 확인. 원천 재수집 성공을 검증하지 않으므로 원천 구조 문제는 개발 담당자에게 전달. |
| 저장 공간·계정 의심 | `6_공통설정과점검` → `previewBriefingHealth` | 고정 실행 계정 검사·속성 용량·봇 탭 행 수 확인. 계정 불일치로 실패하면 회사 실행 계정을 먼저 확인. |

### 개발 담당자에게 보낼 내용

다섯 가지만 전달합니다: **발생 날짜·회차 / 전원 또는 특정 PM / 업무·Slack·회의 중 어느 영역 / 실행 로그의 오류 문구 / 실제 DM과 기대 결과의 차이**. 토큰·키·원본 주소·개인 일정 전체를 복사하지 않습니다.

## 4. PM 한 명 추가

1. 허용된 **봇 전용** BOT_USERS에서 PM 이름·Slack ID·회사 이메일·중복 여부를 확인합니다. 원본 업무 시트는 편집하지 않습니다.
2. 명단 동기화가 필요하면 중앙 봇 `6_공통설정과점검` → `previewRosterFromSlack`로 먼저 대조합니다. `syncBotUsersFromSlack`은 **Slack 조회·BOT_USERS 수정** 함수이므로 대상 확인 후에만 실행합니다.
3. 봇 전용 BOT_USERS E열의 `calendar_connect`를 체크하고, `4_캘린더연결` → `previewCalendarConnectionInvites`로 초대 대상을 확인합니다.
4. **실제 초대 DM:** 같은 파일의 `sendCalendarConnectionInvites`. 지정된 PM에게 메시지가 갑니다. 미리보기에서 대상이 맞을 때만 실행합니다.
5. PM이 회사 계정으로 승인한 후 `previewConnectedCalendarStatus`에서 연결·조회 성공·최근 수집·**자동 갱신 기록**을 확인합니다. 다음 회차의 실제 DM 일정을 본인 캘린더와 대조해야 연결 검증이 끝납니다.

## 5. 중지·재개·재발송

- **전체 DM 중지:** 중앙 봇 프로젝트 설정의 스크립트 속성 `ENABLE_PM_SEND`를 `false`로 변경합니다. 진행 중인 외부 요청을 취소하는 버튼은 아닙니다. Slack 수집·개인 캘린더 갱신도 별개입니다. 이후 추가 DM이 멈췄는지 확인합니다.
- `ENABLE_CONNECTED_PM_SEND=false`는 전체 중지가 아닙니다. 본인 시범 모드로 돌아갈 수 있으므로 전체 중지는 `ENABLE_PM_SEND`로 구분합니다.
- **한 PM만 중지:** 허용된 봇 전용 BOT_USERS의 C열 `send_enabled`를 FALSE로 바꿉니다. 캘린더 동의 철회는 별도 연결 화면에서 처리합니다.
- **재개:** 실패 원인 해결 → 조회 함수로 상태 확인 → 수신 대상 확인 → 기존 스위치 복원 → 다음 정기 회차의 실제 수신 확인 순서입니다.
- **응답 유실·중복 의심:** 수신자에게 실제 수신 여부부터 확인합니다. 발송 기록·점유 속성을 지우거나 정기 함수를 다시 실행하지 않습니다. 로그 재기록이 필요한 복구는 개발 담당자에게 요청합니다.

## 6. 운영자가 임의로 실행하지 않을 것

| 함수·행동 | 이유 |
| --- | --- |
| `sendScheduledBriefing11/14/17`, `resumeConnectedBriefingSend` | 실제 대상 PM들에게 발송할 수 있음 |
| `installBriefingTriggers`, `removePersonalBriefingTriggers` | 자동 발송 예약을 변경함. 현재 실행 계정의 트리거만 대상으로 함 |
| `collectBbpmSnapshot` | Slack 새 조회와 봇 수집 캐시·속성을 변경함. 조회만 하는 진단 함수가 아님 |
| `refreshBotTasks`, `refreshAndPreviewPmBriefings` | 설정된 원천을 읽고 BOT_TASKS·수신자/이력을 변경할 수 있음. 원천 읽기 허용 범위 확인 필요 |
| `switchToOriginalSheets`, `revertToCopySheets`, `applyBotSettings` | 다음 회차가 읽는 대상·기능 설정을 바꿈. 일상 장애 해결에 바로 사용하지 않음 |
| `cleanupBotStorage`, `compactBriefingSendLog` | 기록을 정리함. 먼저 상태 확인 후 허용된 봇 저장소에만 실행 |

**코드 업로드는 개발 담당자 작업**입니다. 원본 수정 → 전체 테스트 → 합본 빌드 → 직전 원격 대조 → 업로드 → 재조회 확인을 따릅니다. 10:15~11:10 / 13:45~14:40 / 16:45~17:40에는 업로드하지 않습니다.

## 7. 운영 인계 체크리스트

- [ ] 후임자가 **본인 회사 계정으로** 중앙 봇·봇 전용 시트·연결 앱에 필요한 접근을 할 수 있다.
- [ ] 기존 실행 계정과 트리거 소유자가 누구인지 확인했다. 파일 접근권만으로 트리거가 후임자에게 이전되는 것은 아니다.
- [ ] 기존·후임 트리거가 동시에 돌아 중복 발송하지 않도록 전환 담당자와 시점을 정했다.
- [ ] Slack 앱 관리 권한·토큰 보관 담당자·실패 알림 수신 경로를 정했다. 비밀 값은 인계 문서에 적지 않는다.
- [ ] 후임자가 위 조회 동선을 따라 오류를 확인하고, 다음 실제 회차 결과를 기록할 수 있다.
- [ ] 실제 수신·캘린더 자동 갱신·피드백 버튼까지 확인한 뒤 기존 담당자 권한을 정리한다.

인계 완료는 **문서를 작성한 상태**와 다릅니다. 후임자의 독립 운영 시험은 아직 별도로 필요합니다.
