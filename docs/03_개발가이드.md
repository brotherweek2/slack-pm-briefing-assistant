## 바꾸는 순서

1. 원본 수정. 함수 이름 끝 `_` = 내부 함수, 없으면 편집기에서 직접 실행하는 함수입니다. 직접 실행 함수를 추가·삭제하면 파일 머리 설명도 고칩니다.
2. 테스트: `node tools/test-local.cjs` — 전부 통과해야 합니다. 바꾼 동작에는 합성 자료로 테스트를 추가합니다.
3. 빌드: `node tools/build-apps-script.cjs`
4. 업로드 전 확인: 원격을 다른 폴더에 `clasp pull` 해서 직전 업로드본과 같은지 봅니다(다른 사람이 바꿨는지).
5. 업로드: `apps-script-deploy/`에서 `clasp push` → 다시 내려받아 일치 확인.
6. 함수 목록 갱신: `node tools/gen-function-list.cjs > docs/함수목록.md`

중앙 봇의 웹 앱(`doPost`)은 연결 앱의 일정 수신과 Slack 버튼(점심 메이트) 응답을 함께 받습니다. `doPost`나 그 아래 코드를 바꾸면 Apps Script 편집기에서 **배포 관리 → 새 버전**으로 웹 앱을 갱신해야 반영됩니다(주소는 그대로).

연결 앱은 `calendar-connector/`에서 `clasp push` 합니다. 화면(`Connect.html`)이나 `doGet`을 바꾸면 웹 앱 배포를 새 버전으로 갱신해야 PM에게 보입니다(링크 주소는 그대로).

## 규칙

- 원본 업무 시트에는 어떤 쓰기도 하지 않습니다.
- 토큰·키·실제 Slack ID·이메일·사람 이름을 코드·테스트·저장소에 넣지 않습니다. 테스트는 `PM A`, `U00000001`, `example.test` 같은 합성 값만 씁니다.
- 실제 발송 함수(`send…`)는 사람이 편집기에서 실행합니다.
- 정기 회차 중(10:15~11:10, 13:45~14:40, 16:45~17:40(정기 회차 ±15분 + 이어 보내기 20분))에는 업로드하지 않습니다.
- 한 번에 한 사람(또는 한 에이전트)만 원본을 고칩니다.

## 파일 머리 주석 형식

원본 파일 맨 위 주석은 모두 같은 형식입니다. 함수를 추가하거나 동작을 바꾸면 이 주석도 함께 고칩니다(`docs/함수목록.md`는 이 주석에서 자동으로 만듭니다).

```text
/**
 * 09. 자동실행 — 이 파일이 하는 일 한 줄
 *
 * 알아둘 것                ← 꼭 지켜야 할 주의사항만 1~4줄
 * - …
 *
 * 직접 실행 (🔍 조회만 · ⚠️ 보내거나 바꿈 · ⏰ 자동 호출)
 * - ⚠️ installBriefingTriggers(): 핵심 한 문장
 *
 * 내부 함수 (직접 실행하지 않음)
 * - sendScheduledBriefing_(slot): 핵심 한 문장
 */
```

## 공개 저장소 만들기 (관리자)

로컬 작업 폴더에서 `node tools/prepare-repository.cjs`를 실행하면 `.github-sync/`에 공개본을 만듭니다. 이 과정에서 시트 ID·회사 도메인·Slack ID·사람 이름을 예시 값으로 바꾸고, 남은 식별자가 있으면 멈춥니다. 이 도구 자체와 운영 기록은 공개하지 않습니다.
