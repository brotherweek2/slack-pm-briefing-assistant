# 06. '업무 없음'과 '수집 실패' 점검

## 조사 범위와 결론

2026-10-28 로컬 원본 코드와 합성 자료로 조사했습니다. 실제 원본 업무 시트·Slack·캘린더를 새로 조회하거나 정기 함수를 실행하지 않았습니다. 아래는 **코드에서 확인한 동작과 모의 재현 결과**이며 실제 운영 누락 건수는 아닙니다.

**명시적인 API·탭·머리글 오류는 대체로 구분되지만, 형식은 맞고 개별 데이터만 해석되지 않는 경우까지 완전하게 구분하지는 못합니다.** '확인할 특이사항 없음'은 전체 업무가 없다는 보장이 아닙니다.

## 합성 재현

- 새 양식 담당 탭의 정상 프로젝트 표기 `12345 · 10/30 · 1,000개 · 최대 2배치`는 1건 인식.
- 구분자만 `/`로 바꾼 같은 프로젝트는 담당 탭 자체는 1개로 인식되지만 프로젝트 0건, 수집 예외 없음.
- 담당 탭이 없는 합성 입력도 담당 탭 수집기 자체는 예외를 발생시키지 않음.
- 오전 기록 조회는 기록 없음에 null을 반환하고, 새 업무·Slack 없음으로 문안을 만들면 오후 '새로운 알림 없음'이 됨.

프로젝트 형식이 실제로 달라졌다는 주장이 아니라 **이런 변화가 발생했을 때 0건과 실패를 구분할 장치가 부족하다는 재현**입니다.

## 보완 제안 — 아직 운영 코드 반영 전

1. **원천별 수집 결과:** 성공·실패·부분 확인 / 조회 시각 / 읽은 행 / 조건 일치 / 형식 미해석 / 담당자 미확정 건수를 구분해 봇 전용 저장소에 기록. 원본 주소·개인정보를 추가 저장하지 않음.
2. **PM별 확인 범위:** 담당 탭 인식과 프로젝트 해석 성공을 업무 존재 여부와 분리. 담당 탭이 없는 사실만으로 실제 역할 변경을 단정하지 않기. 기존 담당 탭을 잃으면 구조 확인 요청.
3. **실패 시 보존:** 새 수집이 불완전하면 기존 업무를 일괄 비활성화하지 않고 직전 성공본을 보존. 오래된 자료임을 표시하고 관리자에게 원인 안내.
4. **0건 문구:** 모든 필요한 원천·담당자·파싱이 확인되면 '현재 조건에 맞는 알림 업무 없음'. 부분 확인이면 '일부 업무 확인 필요'. 조회 실패는 '업무 확인 실패'로 분리.
5. **14시 비교 기준:** 오전 발송 기록이 없으면 '오전 기록이 없어 업무 변화 비교 불가'를 실제 DM에 표시. 필요한 경우 현재 업무를 대체 안내하는 정책을 별도 결정.
6. **상태값 감시:** 기존 키워드를 늘리는 방식과 별개로, 처음 보는 상태·프로젝트 형식은 자동 완료로 판단하지 않고 관리자 확인 대상으로 모으기.

## 운영자가 지금 할 수 있는 확인

[운영자 빠른 시작](00_운영자빠른시작.md)의 조회 함수 순서를 사용합니다. `previewBriefingAccuracy`는 **이미 적재된 BOT_TASKS와 저장 Slack**만 비교합니다. 이 함수에서 0건이라고 나온 것이 원천을 빠짐없이 읽었다는 증거는 아닙니다.

원천 대조가 필요하면 사용자에게 목적·탭·필드 범위를 명시적으로 허용받은 뒤 최소 조회합니다. 원본 시트는 수정하지 않습니다. 새 함수·저장 형식·자동 복구 정책을 반영하려면 별도 코드 변경과 회귀 검증을 거쳐야 합니다.
