# 06. '업무 없음'과 '수집 실패' 점검

## 조사 범위와 결론

2026-10-28 로컬 원본 코드와 합성 자료로 조사했습니다. 실제 원본 업무 시트·Slack·캘린더를 새로 조회하거나 정기 함수를 실행하지 않았습니다. 아래는 **코드에서 확인한 동작과 모의 재현 결과**이며 실제 운영 누락 건수는 아닙니다.

**명시적인 API·탭·머리글 오류는 대체로 구분되지만, 형식은 맞고 개별 데이터만 해석되지 않는 경우까지 완전하게 구분하지는 못합니다.** '확인할 특이사항 없음'은 전체 업무가 없다는 보장이 아닙니다.

## 합성 재현

- 새 양식 담당 탭의 정상 프로젝트 표기 `12345 · 10/30 · 1,000개 · 최대 2배치`는 1건 인식.
- 구분자만 `/`로 바꾼 같은 프로젝트는 담당 탭 자체는 1개로 인식되지만 프로젝트 0건, 수집 예외 없음.
- 담당 탭이 없는 합성 입력도 담당 탭 수집기 자체는 예외를 발생시키지 않음.
- 오전 기록 조회는 기록 없음에 null을 반환하고, 새 업무·Slack 없음으로 문안을 만들면 오후 '새로운 알림 없음'이 됨.

프로젝트 형식이 실제로 달라졌다는 주장이 아니라 **이런 변화가 발생했을 때 0건과 실패를 구분할 장치가 부족하다는 재현**입니다.

## 보완 제안 — 아직 운영 코드 반영 전

1. **원천별 수집 결과:** 성공·실패·부분 확인 / 조회 시각 / 읽은 행 / 조건 일치 / 형식 미해석 / 담당자 미확정 건수를 구분해 봇 전용 저장소에 기록. 원본 주소·개인정보를 추가 저장하지 않음.
2. **PM별 확인 범위:** 담당 탭 인식과 프로젝트 해석 성공을 업무 존재 여부와 분리. 담당 탭이 없는 사실만으로 실제 역할 변경을 단정하지 않기. 기존 담당 탭을 잃으면 구조 확인 요청.
3. **실패 시 보존:** 새 수집이 불완전하면 기존 업무를 일괄 비활성화하지 않고 직전 성공본을 보존. 오래된 자료임을 표시하고 관리자에게 원인 안내.
4. **0건 문구:** 모든 필요한 원천·담당자·파싱이 확인되면 '현재 조건에 맞는 알림 업무 없음'. 부분 확인이면 '일부 업무 확인 필요'. 조회 실패는 '업무 확인 실패'로 분리.
5. **14시 비교 기준:** 오전 발송 기록이 없으면 '오전 기록이 없어 업무 변화 비교 불가'를 실제 DM에 표시. 필요한 경우 현재 업무를 대체 안내하는 정책을 별도 결정.
6. **상태값 감시:** 기존 키워드를 늘리는 방식과 별개로, 처음 보는 상태·프로젝트 형식은 자동 완료로 판단하지 않고 관리자 확인 대상으로 모으기.

## 사례: Slack 칸 "기타 오류" — 설정 바꾼 직후 (11/24)

- **증상:** 미리보기·DM Slack 칸에 "읽어오지 못했습니다 — 사유: 기타 오류 (마지막 완료 수집 HH:MM)".
- **원인:** 수집이 끝난 뒤 PM 그룹이나 판소리 설정(`PANSORI_THREADS`·수신자)을 바꿈. 수집본에 저장된 설정과 지금 설정이 달라 그 수집본을 쓰지 않는다(`CONFIG_CHANGED`, 잘못된 사람에게 예전 자료가 가는 것을 막는 안전장치).
- **조치:** 다음 수집 완료를 기다리거나 `collectBbpmSnapshot`을 수동 실행. 앞으로는 수집 시간대 전에 바꾼다. 자세한 흐름은 [10 Slack 수집과 시트 적재](10_슬랙수집과적재.md).
- **보완 (11/24 밤 반영):** 판소리 설정만 바뀐 경우는 이제 Slack 칸을 비우지 않는다(BBPM 그대로, 판소리는 겹치는 부분만). PM 그룹이 바뀐 경우만 비우고, 사유는 "Slack 설정 변경 뒤 아직 다시 수집 전 (다음 수집 뒤 반영)"으로 나온다. 관리자 요약·미리보기에도 경고가 뜬다.

## 사례: PM Review 업무가 갱신되지 않음 — 원본 시트 이동 (11/24)

- **증상:** 정기 DM 기준 줄 아래 "⚠️ PM Review 시트를 읽지 못해 해당 업무는 직전 확인 결과예요", 관리자 요약에 "업무 시트 읽기 실패(직전 결과 유지)". 새 1차 검수가 안 들어오고 끝난 건이 계속 보일 수 있음. `previewOriginalSheetConnection`은 "PM Review 탭이 없습니다"로 실패.
- **원인:** PM Review 탭이 다른 스프레드시트로 옮겨짐. 봇은 그 업무 종류만 직전 결과로 유지하고 나머지는 새로 읽어 보낸다(회차 전체를 멈추지 않음). 경고가 나오므로 관리자 요약을 볼 것.
- **조치:** 새 시트에 PM Review 탭과 머리글(언어쌍 / Status / 1차 검수 / 1차 검수 기한, 1~5행 중 한 줄)이 있는지 확인 → BOT_SETTINGS `ORIGINAL_PM_REVIEW_SPREADSHEET_ID`에 새 주소 → `applyBotSettings` → `switchToOriginalSheets`(새 시트만 검사, 예전 시트가 깨져 있어도 됨). 되돌리기 `revertToCopySheets`.

- **같은 파일 안에서 탭만 바뀐 경우 (11/26):** 새 탭 이름이 정확히 "PM Review"이고 그 이름의 탭이 하나뿐이며 머리글이 맞으면 아무것도 하지 않아도 된다(봇은 탭을 이름으로 찾음). 탭 이름이 다르거나 같은 이름이 둘이면 읽기 실패 경고가 뜬다.
- **상태 기준:** DM에 넣는 상태는 "검수 Agent 완료"·"1차 검수중"뿐. "1차 검수 대기"·"교차검증 중" 등 다른 상태는 의도적으로 제외(11/26 담당자 결정).

## 경고를 놓치지 않게 (11/24 밤)

- **관리자 요약:** 처리할 것이 있으면 제목 바로 아래 `🚨 확인할 것 N건`. 이상 없으면 맨 아래 `✅ 이상 없음`만.
- **미리보기(`previewMyMorningBriefing`):** 원본을 새로 읽지 않으므로 로그 맨 끝에 ⚠️로 알린다 — 오늘 아직 업무 갱신 전 / 마지막 갱신에서 읽지 못한 시트(직전 결과 유지) / 최근 Slack 수집 오류 / 판소리 설정 변경.

## 운영자가 지금 할 수 있는 확인

[운영자 빠른 시작](00_운영자빠른시작.md)의 조회 함수 순서를 사용합니다. `previewBriefingAccuracy`는 **이미 적재된 BOT_TASKS와 저장 Slack**만 비교합니다. 이 함수에서 0건이라고 나온 것이 원천을 빠짐없이 읽었다는 증거는 아닙니다.

원천 대조가 필요하면 사용자에게 목적·탭·필드 범위를 명시적으로 허용받은 뒤 최소 조회합니다. 원본 시트는 수정하지 않습니다. 새 함수·저장 형식·자동 복구 정책을 반영하려면 별도 코드 변경과 회귀 검증을 거쳐야 합니다.
